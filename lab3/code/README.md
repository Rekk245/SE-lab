# 合账：多人共享记账系统

软件工程实验三，王紫涵，241220012。依据实验一需求及实验二 UML 实现。

## 运行

需要 **Python 3.12 或更新版本，并包含 Tkinter**。开发验证环境为 Windows 11、Python 3.13.7。应用运行只使用 Python 标准库，不需要安装第三方包。

在本目录运行：

```powershell
python run.py --demo
```

也可双击 `启动演示.bat`。演示账号 `张三`、`李四`、`王五`、`赵六` 对应 4级、3级、2级、1级；演示密码均为 `Demo2026!`。演示报价链接使用 example.com 占位，不表示真实交易。

第一次使用 `--demo` 会在空数据库中建立演示数据；数据库非空时不重复生成账目；只对可识别的旧版四个内置演示账号升级中文姓名，保留身份关系、密码和账目。成员编号按注册顺序稳定分配为 `SL001`、`SL002` 等；邀请支持输入成员编号或账号名。成员表只显示“成员编号、姓名、等级”，等级只控制权限，不代表姓名。

默认数据库在当前工作目录的 `data/ledger.sqlite3`。

创建自己的空数据库：

```powershell
python run.py --db data/my-ledger.sqlite3
```

在登录页注册账号，登录后创建账本。其他账号注册后，由账本创建者邀请，对方登录接受邀请。退出登录可更换账号；多个进程可使用同一个本地数据库文件，不代表已经实现跨电脑联网服务。

## 验证邀请与移出

演示库预先创建了四个未加入账本的候选账号，密码同为 `Demo2026!`：`SL005 陈晨`、`SL006 林悦`、`SL007 钱七`、`SL008 孙八`。候选账号没有该账本的权限等级，接受邀请后才成为 2级成员。

1. 用张三登录，在“账本与成员 → 邀请与退出”输入 `SL007` 并发送邀请。
2. 退出登录，改用钱七登录，在“收到的邀请”接受。此时账本成员由 4 人变为 5 人。
3. 再以张三登录，在成员表选择 `SL007 钱七`，点击“移出账本”并填写原因。成员恢复 4 人，钱七旧会话也失去该账本访问权限。
4. 张三可重新邀请钱七，编号仍是 `SL007`；`SL008 孙八` 可用来独立重复流程。

只有 4级最高管理可以移出其他成员。未完成申请、未结款项或唯一最高管理约束会阻止离开；移出保留用户、历史账目和日志，不删除账号。

## 操作顺序

1. 在“账本与成员”创建账本、邀请成员、接受邀请并设置角色。
2. 在“收支查询与录入”提交支出，填写金额、类别、日期、报价链接与模式。均摊时多选成员。
3. 在收支列表选中账目，进入“申请与审核”。管理员批准申请；申请人登记付款、确认使用；管理员完成审核后入账。普通管理员不得自审，最高管理员也须显式确认。
4. 每次操作后列表刷新，需要重新选择账目再进行下一步。实际付款人可选择团队或某个成员。
5. 改价前若已付款，须先登记全额退款到账并核平，再载入申请、修改、重新审核。系统不连接银行，不自动判断到账。
6. “预算与统计”查看月/年数据，最高管理员设置预算；超额会提示但不会阻止继续申请。
7. “分摊与结算”选择一条债务，登记已实际发生的线下收付款。结清不增加收支。
8. 在收支列表选择已完成记录，最高管理员在“更正与日志”作废或创建更正申请。更正记录重新审核；已结付款不改写，通过反向债务体现差额。

组合查询中的“成员”指申请人；成员费用承担另在均摊统计及账目详情展示。业务日期决定月/年统计归属。全账本成员可看本账本业务摘要，日志限管理员及最高管理员。

python dist/shared_ledger.pyz --demo

无窗口业务演示：

```powershell
python run.py --headless-demo --db data/fresh-demo.sqlite3
```

图形界面控件检查（需要桌面环境）：

```powershell
python -m tools.gui_check
```

这会逐一打开四角色的六个页面，在 1280×729、1180×710 和 960×600 窗口检查控件边界、首页四整行成员及页面滚动，并补测高 DPI 设置，并核对账目选择、更正预览、结算模式筛选和余额默认值；它不替代截图审阅和完整人工操作测试。

## 代码组织

| 模块 | 职责 |
| --- | --- |
| `domain.py` | 金额、角色、状态及 Transaction/Expense/Income 快照 |
| `database.py` | SQL 表结构、外键、唯一约束、事务和手动备份 |
| `auth.py`、`base.py` | 本地登录、账本权限、自审约束、审计及请求回执 |
| `membership.py` | 账本、邀请、角色、退出和类别维护 |
| `workflow.py` | 收支申请、改价、审批、付款、使用、退款与撤销 |
| `posting.py` | 完成入账、分摊债务、作废及关联更正 |
| `settlement.py` | 线下结清和分配 |
| `query.py` | 组合筛选、统计、预算、日志、CSV 导出和保留说明 |
| `ui.py`、`ui_pages.py`、`ui_design.py`、`ui_presenter.py` | 手写事件处理、侧栏卡片布局、主题及真实数据图表，无 GUI 代码生成器 |
| `demo.py` | 使用公开业务服务生成演示数据 |
| `tests/`、`tools/` | 独立验证与构建工具，不计入应用源码统计 |

## 已知范围与待确认事项

- 原 UML 中的 Web/API/PostgreSQL 改为本地 Tkinter/服务调用/SQLite；SQLite 写事务串行化，不等价于服务器的高并发部署。
- 登录保护应用内操作，本地数据库文件仍由电脑使用者控制。未实现远程令牌、防暴力登录或生产部署。
- 数据保留策略固定为 `UNDECIDED`。由于实验一未解决“仅金额永久保存”与历史统计、跨期结算的矛盾，未实现破坏性清理；不能声称已满足最终保留验收要求。演示库不应用于长期真实业务。
- 报价只实现 HTTP(S) 链接引用，未实现截图上传、受控附件服务器。
- 一笔支出登记一个实际付款主体；不支持一笔费用由多个人分次共同垫付。只支持全额退款核平，不支持部分退款建模。
- 类别支持新增，未实现重命名或删除；备份提供底层手动接口，未实现定时备份及自动恢复。
- 并发测试验证一致性，200 人测试验证成员规模；未验证 20 并发、万条数据、95% 两秒响应的候选指标。
- `Session` 是桌面进程内部对象，不能当作可以传给不可信客户端的认证凭据。
- 需求中的候选规则是本实验实现选择，详见实验报告；不表示甲方已确认。提交前仍须本人逐行阅读源码并确认个人判断。
